Get the backend running: database, migrations, seeds

Backend2hDepends on: none

Nothing can be demoed until the backend talks to a real database. This ticket gets it working.

What you will see working

Register and login work for real, and the API returns the diagnostic questions and the full syllabus.

Files you'll touch

  • .env
  • src/db/ (migrations and seed scripts)

How to build it

Copy the correct connection string from your Supabase dashboard and URL-encode special characters in the password (@ becomes %40). Run the migrations and both seed scripts. Set your AI key and test one real AI review. Push both repos so your teammate has the same code.

Definition of done

  • Registering a new user works.
  • A diagnostic submit returns an AI review.
  • The syllabus endpoint returns all 4 levels.

How to check your work

curl register, login, /diagnostic/questions and /api/syllabus

13

Lesson endpoint: AI-written lessons, saved and reused

Backend4hDepends on: SYL-11

Writing 160 lessons by hand isn't realistic. The AI writes each lesson the first time someone opens it, and the result is saved so it's instant afterwards.

What you will see working

Opening any concept returns a short lesson with an explanation, a Python example and a common mistake.

Files you'll touch

  • schema.ts (lesson_content table)
  • services/lessonService.ts (new)
  • GET /concepts/:id/lesson

How to build it

Store one lesson per concept. If it exists, return it. Otherwise ask the AI service for a short lesson and save it. If the AI fails, return a simple lesson built from the concept's description without saving it, so a later visit can retry.

Definition of done

  • The first request generates and saves a lesson.
  • The second request is instant.
  • With the key removed, a readable lesson still returns.

How to check your work

Call the lesson endpoint twice, then once with the AI key removed
14

Progress, XP and streak endpoints

Backend4hDepends on: SYL-11

Remembers which concepts each user has finished and rewards them.

What you will see working

Completing a concept raises the user's XP and streak, and progress counts show per topic and per level.

Files you'll touch

  • schema.ts (user_concept_progress table)
  • progressRoutes.ts and progressController.ts (new)

How to build it

One row per user and concept with a status of started or completed. POST /progress/concepts/:id/start, POST /progress/concepts/:id/complete (10 XP, and completing twice must not award XP twice) and GET /progress with completion per topic and level. Streak: add 1 if the last active day was yesterday, keep it if today, otherwise reset to 1.

Definition of done

  • Completing a concept twice awards XP once.
  • The streak behaves for today, yesterday and a gap.
  • GET /progress counts are correct.

How to check your work

Complete the same concept twice, then check xp on /me
15

Practice quiz endpoints

Backend5hDepends on: SYL-13, SYL-14

After reading a lesson, the user can test themselves. Questions are AI-generated and saved, with hand-written backups so the demo never breaks.

What you will see working

Each concept has a 5-question practice quiz that is graded and awards bonus XP.

Files you'll touch

  • schema.ts (practice_questions table)
  • practiceRoutes.ts and practiceController.ts (new)
  • src/db/seed-practice.ts (new)

How to build it

GET /concepts/:id/practice returns 5 multiple-choice questions without the answers. If none are saved, generate and save them with the AI. POST /concepts/:id/practice/submit grades on the server, returns the score with explanations, and awards 5 XP per correct answer. Hand-write 5 backup questions for about 6 concepts and use them if the AI fails.

Definition of done

  • The questions endpoint never exposes correct answers.
  • A perfect score awards 25 XP.
  • With the AI key removed, the backup questions still return for the seeded concepts.

How to check your work

Fetch questions, submit answers, check the XP on /me

Register to onboarding flow and login routing

Frontend3hDepends on: SYL-11 for real data

Right now registering ends at a pop-up and users must find the login page themselves.

What you will see working

Signing up drops the user straight into onboarding, real error messages show, and returning users skip the steps they've done.

Files you'll touch

  • src/lib/api.ts (new)
  • register-page.tsx
  • login-page.tsx

How to build it

Create one shared API file with the backend address in an environment variable, and use it in every page instead of the hardcoded address. On register: show the backend's real error text, save the token, go to /onboarding. On login: check /me afterwards and go to onboarding, then the diagnostic, then the syllabus depending on what the user has finished.

Definition of done

  • A duplicate email shows Email already in use.
  • Register goes straight into onboarding.
  • A returning user lands on the syllabus.

How to check your work

Register a new user, log out, log in again
